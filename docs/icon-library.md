# SVG icon collection

The public collection is at https://designsystem1.com/icons. Interface icons use real vector geometry in a 16 × 16 coordinate space. They are separate from the gridded badge/favicon editor, which remains available in its own tab.

## Add an icon from a request

1. Inspect neighbouring icons in `DS1/x-icon/` and the Figma source collection before drawing. Match their optical weight, spacing, curves, and alignment; avoid rasterizing curves into cells.
2. Add a descriptively named, kebab-case SVG to `DS1/x-icon/`. Use `width="16" height="16" viewBox="0 0 16 16"`, self-contained vector paths, and `currentColor` for monochrome artwork. Use explicit fills when colour is part of the design. Do not embed scripts, event attributes, images, fonts, external resources, or links.
3. `vp run icons:build` automatically discovers the SVG, validates it and adds it to the public collection. No manual gallery list or frontend code change is needed for a new icon.
4. Run `vp test --run tests/interfaceIcons.test.ts tests/iconGrid.test.ts tests/iconStudio.test.ts`, then `vp run site:build`. Publish through the existing site deployment workflow when requested, and verify the public SVG and page assets by HTTP. Respect the user's browser-testing preference.

## Source collection

The reference is Figma file `XAnoaRoq9LxVAHUZgtdO0r`, frame `403:4105`. Its 72 original SVGs, less the three panel icons since removed as unused (`panel`, `pleft`, `pright`), are stored in `website/public/icons/interface/`; metadata is in `website/src/lib/icons/figma-interface.json`. These assets preserve the original Figma icon coordinates, transforms, and clipping in their 16-unit frames. The export renderer’s page background and purple component-set boundary were removed; the icon layers were not redrawn. Existing additions with smaller bounds are centred without changing their paths. `note-page` and `title-text` distinguish identically named Figma components.

The catalog includes the original reference icons, additional loose Figma drawings recorded in `website/src/lib/icons/figma-additions.json`, and shared interface icons in `DS1/x-icon/`. The loose drawings retain their source node links and geometry; coloured frame backgrounds are presentation surfaces and are excluded from exports. 30-unit drawings are scaled as a whole into the 16-unit overview grid.

Product-specific artwork belongs to its product. `icon-scope.ts` excludes Ezo and Aa-prefixed imports, coloured badges, block and pattern thumbnails, and arrangement/navigation collections from the shared overview and its public SVG exports. Shared icon labels are one semantic word, without product names. Use `icon` as the shared symbol for artwork; `image` is retired from the collection and its public exports. Variations of one concept share that word; their existing technical keys and Figma node references distinguish the drawings. Repeated drawings appear once in the shared collection: `interfaceIconAliases` records their canonical keys and prevents old runtime copies from being rediscovered as additions. Compare the rendered geometry when checking duplicates, including tiny coordinate rounding differences; matching names alone do not make different drawings duplicates. Existing runtime copies remain for compatibility with product consumers; their presence there does not make them shared icons. Future product imports must respect this boundary. Existing names are not silently replaced: a reference name takes precedence in the gallery. To refine a reference icon, update its source SVG deliberately and compare it with the linked Figma component; update the runtime counterpart in `DS1/x-icon/` only when the requested scope includes it.

`scripts/build-interface-catalog.ts` produces the generated `interface-catalog.json`, public `/icons/catalog.json`, and public copies of added SVGs. Do not edit those generated files directly. The Original/Outlines/Both inspector changes the display only; copying or downloading the main SVG returns the untouched source. The separate outline download exports a stroked construction view.

Prompted additions are performed through the development conversation, not an in-page AI service. The page's Copy request control packages the description and these repository conventions for that workflow.

## Product icon coverage

Run `vp run icons:sync-products` to import the Ezo runtime map, UI SVG assets, settings glyphs, native screen SVGs, static inline controls, flat badges and their 3D forms, and Aa’s editing SVGs. It records each source and the installed drawing in `DS1/x-icon/product-sources.json`. Run `vp run icons:check-products` to check for drift against both product checkouts. Existing library drawings stay intact; a different product drawing gets an Ezo or Aa name. Duplicate is the reference Command-D drawing in all three products. Globe uses one unioned vector path so adjoining pieces cannot leave seams.

For these shared refinements, change the SVGs here and run `vp run icons:sync-consumers`. It synchronizes Globe across Ezo (web, iPhone and Android), Consistency (Lit and React), Link (web and iPhone), and tau99, then updates Duplicate in Ezo and Aa, regenerates Ezo’s icon chunks, and refreshes the built Aa snapshot. `vp run icons:sync-globe` updates only Globe; `vp run icons:check-globe` verifies all its consumers without writing. The canonical source is `DS1/x-icon/globe.svg`; native Swift paths and React adapters are generated from that exact path. Keep display sizes, including 30px, separate from the 16-unit drawing grid. The Android library name remains a compatibility alias of Globe, not a separate drawing. Then run `vp run icons:sync-products` to refresh the inventory and its checks.

The collection’s optical stroke weight is not a universal 1px. Preserve the source measurements, including 0.92-unit strokes, and the geometry of filled outlines. A construction outline in the inspector is a display aid, not the icon’s stroke width. Do not round artwork to 1px during import or regeneration.
