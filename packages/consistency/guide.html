Aa edits text. Consistency builds sites.

This is the guide for our main development editor. We develop and test the two layers together here, while keeping their responsibilities separate.

Aa: the vanilla text editor

Aa is a vanilla TypeScript editor with a framework-independent DOM API. It works on its own. The <aa-editor> element and optional adapters wrap that engine.

  • Writing: typing, paste, IME composition, caret and native text selection, Markdown blocks, formatting and text undo.
  • Text controls: the formatting toolbar, slash commands and the editor’s focus and dismissal behavior.
  • Extension points: generic atoms, commands and optional block movement. Products provide their own content types, transport and permissions.

Escape leaves editing. It closes Aa’s controls, clears its selection and removes the blinking caret without changing the document. Escape during IME composition remains with the input method. Click into the text to write again.

Consistency: the site-building expansion

Consistency composes Aa text with website components. It owns page layout, responsive desktop/mobile previews, visual gaps and padding, resizing, page-level marquee selection and section reordering.

Cards, buttons, image carousels, page destinations, library choices and linked component design belong to this expansion. With Consistency enabled, matching components share design while keeping their own text.

Adding page content

The approved additions are List, Tabs, Table, Carousel, Image, Link and Icon. Find them with / or Block commands. The inline prompt can insert these same defaults. Lists, tabs, tables and links use Aa’s native editing. Drop an image onto its placeholder or choose a file; double-click an icon, or press Enter on it, to change its name in place. These additions have no Edit buttons or modal editing forms.

Seeing the page structure

Turn on Grouping in Composition controls to see the actual containers: sections move together, rows and columns arrange related elements, and cards keep their content together. Solid outlines mark sections; dashed outlines mark nested groups. These are layout relationships, not a claim that the words have the same meaning. The layer does not create groups or change the page. Component names is a separate layer for identifying individual elements.

Shared foundations

Design system 1 supplies the grid, type, colours and reusable controls. Drag supplies movement and settling. Aa uses those foundations for text blocks; Consistency uses them for page composition. A shared foundation does not make the two editors one module.

Where a fix belongs

  • A blinking caret, text selection or formatting problem: fix Aa, test it without the site builder, then bring its committed build into the development editor with Sync 1.
  • A page gap, card size or linked design problem: fix the Consistency expansion, using Aa’s public API for text.
  • A shared control, grid or drag problem: fix the owning foundation, then update its consumers deliberately.

No Consistency workaround should duplicate Aa’s keyboard or focus logic. Text remains Markdown; site composition and component design remain the expansion’s responsibility.

Developing here
