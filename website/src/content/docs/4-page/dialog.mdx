title: Dialog
description: A shared modal with native focus and form behavior.
---

`ds-dialog` owns modal behavior and appearance around a light-DOM `<dialog>`.
The native element keeps labels, descriptions and form controls in one tree.
Opening it uses `showModal()`; the browser supplies the top layer and inert background.

```html
<ds-dialog open>
  <dialog aria-labelledby="example-title">
    <h2 id="example-title" data-ds-dialog="title">Example dialog</h2>
    <button type="button" data-ds-dialog-dismiss>Close</button>
  </dialog>
</ds-dialog>
```

Set the host's `open` property to open or close it. `closeOnEscape` and
`closeOnBackdrop` default to true. The cancelable `ds-close-request` event has
a `detail.reason` of `escape`, `backdrop`, `outside`, `button` or `native`. Prevent its
default action when the application must decide whether closing is allowed.
Nested dialogs retain the background scroll lock until the last one closes.
The lock fixes the body at its current offset, then restores its original inline
styles and scroll position, including when an underlying dialog closes first.

Select `dialog` in the source snapshot to include the optional React adapter:

```tsx
import { Dialog, DialogContent, DialogHeader, DialogTitle, DialogDescription }
  from "./design/react/dialog";

<Dialog open={open} onOpenChange={setOpen}>
  <DialogContent closeLabel="Close">
    <DialogHeader>
      <DialogTitle>Example dialog</DialogTitle>
      <DialogDescription>Content and actions belong to the app.</DialogDescription>
    </DialogHeader>
  </DialogContent>
</Dialog>
```

The adapter links the title and description, portals the content into the body,
and provides the shared close button. It does not import Lit during server
rendering; register the selected components in the browser before mounting it.
Use `DialogFooter` for actions. `showClose={false}` is available when content
already includes an accessible close action. A controlled root stays open when
its `onOpenChange` handler declines a request. The optional second argument is
the close reason, so products can distinguish Escape cancellation from a close
button while DS1 remains responsible for handling the keyboard.

The default width is 20 squares, padding one square, with square corners and
no shadow. Set `--ds-dialog-width` for a different whole-square width. Colours,
type and scale follow the shared `--ds-*` tokens. Portals used by menus or
popovers inside a modal must stay inside the native dialog or use the browser's
own top layer; body-level overlays are outside the modal's interactive area.

`DialogContent fullScreen` fills the viewport for document viewers, without
invoking the Fullscreen API. `flush` removes the default padding and gap when
the content already provides its own spacing. Set `--ds-dialog-height` for a
tall, bounded frame. Content layouts still belong to the application; the
shared frame supplies its paper, type, border, backdrop and modal behavior.
`rotated` turns a document frame 90 degrees and swaps its viewport bounds,
keeping its normal margins. Applications decide when to offer rotation.

Aa mounts its floating toolbar, menus, find controls and link field inside the
closest native dialog. Sync Aa before placing an older editor copy in a modal.

## Modeless panels

Set `non-modal` on `ds-dialog` to use native `show()` without a top layer or
inert background. Use `data-ds-dialog-inline` on its native dialog for a panel
in the document flow. In React, use `DialogContent nonModal`; `portal={false}`
keeps the panel inside its product layout or containing modal. `closeOnOutside`,
`blockOutside`, `holdScroll` and `anchor` configure the same Lit behavior. A
native `ref` points to the light-DOM dialog. Set the mode before opening.
The shared stylesheet also installs into a containing
shadow root, so Lit products use the same frame without copying its CSS.

Floating panels can opt into `close-on-outside` and `block-outside`: the outside
click closes the panel and does not activate the control behind it. A gesture
started inside stays inside. Escape closes only the top shared panel. Set
`hold-scroll` to hold the page without fixing or moving its body. Nested modal
and modeless panels release only their own scroll hold. Modeless panels do not
steal focus back from an outside control that has already received it.

`await element.show()` waits for native opening and the first render of its
controls. `element.close()` closes and releases its hold immediately; camera
and media cleanup still belongs to the product's close handler.

Use `element.show({ immediate: true })` only when a rendered control must take
focus inside the opening gesture, such as a phone's search keyboard. The native
frame opens synchronously; focus that control before awaiting the returned
promise. Nested shared menus and inputs render synchronously too. When a new
input is added to an already open panel, `input.renderNow()` exposes its native
field before gesture-time focus. The usual `show()` waits for child controls before opening. Modeless
Escape is handled after a nested editor can cancel it, and keyboard scrolling
inside the panel remains available while the page behind is held.

Configure floating placement with `--ds-dialog-inset`, `--ds-dialog-margin`,
`--ds-dialog-width`, `--ds-dialog-max-width`, `--ds-dialog-max-height` and
`--ds-dialog-layer`. Transparent media frames may set `--ds-dialog-paper` and
`--ds-dialog-border`. `--ds-dialog-padding` also applies to full-screen panels.
Use `--ds-dialog-overflow: hidden` when a bounded layout provides its own
scrolling regions. Set the opening mode before opening a panel.

For a menu opened at a pointer or control, set `element.anchor = { x, y }`
in viewport coordinates before opening. DS1 bounds it to the visible viewport
with half a square of clearance and updates after content, window and mobile
keyboard resizing. `element.place()` is available after a synchronous content
change; reset `anchor` to `null` for ordinary dialog layout. Products do not
need resize listeners or clamping code. Anchored panels can hold a compact
`ds-menu`, whose arrow keys skip disabled/hidden choices and leave text editing
keys to their fields. Keep the panel's accessible label on its native dialog.
