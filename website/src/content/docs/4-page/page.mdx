A page places units on the grid: navigation, content and optional supporting areas, in one of six layouts. See the full-page [Examples](/start-here/examples/) for all six.

## Try it

<ComponentExample example="page" />

## Use it

```html
<ds-page layout="sidebar" divided>
  <ds-sidebar slot="nav" label="Projects"></ds-sidebar>
  <ds-row slot="header" fill>…</ds-row>
  <ds-list>…</ds-list>
</ds-page>
```


## Areas

Every layout has the same five areas, so content moves between layouts without being rewritten. An area with nothing in it takes no room.

| Area | Put it there with | Holds |
| --- | --- | --- |
| Header | `slot="header"` | The page's title and its main actions, along the top of the main area. |
| Nav | `slot="nav"` | Navigation, or the list in List and detail. The leading column. |
| Main | No slot | The work itself. |
| Aside | `slot="aside"` | Properties or related things. Its own column in Inspector, under the main area elsewhere. |
| Footer | `slot="footer"` | Closing actions such as Save, along the bottom of the main area. |

## Widths

Every column is a whole number of squares. Between columns there are two squares, between areas down the page one, and one around the page.

| Layout | Leading column | Main | Trailing column |
| --- | --- | --- | --- |
| `sidebar` | 12 squares | The rest | — |
| `split` | 16 squares | The rest | — |
| `inspector` | 12 squares | The rest | 12 squares |
| `column` | — | 32 squares, centred on the grid | — |
| `centered` | — | 16 squares, centred on the grid both ways | — |
| `tiles` | — | 12-square tiles | — |

Below 30 squares of width every layout becomes one column, navigation first. The layout follows the width of its own container, not the window, so a page inside a panel stacks when the panel is narrow.

## Attributes

| Attribute | Default | What it does |
| --- | --- | --- |
| `layout` | `sidebar` | `sidebar`, `split`, `inspector`, `column`, `centered` or `tiles`. |
| `divided` | false | Draws a hairline between the columns. |
| `measure` | — | The width of the `column` or `centered` column, in whole squares. |
| `fill` | false | Takes its container's full height; each column scrolls on its own. |
| `view` | false | Outlines each area and names it, for inspection. |
| `drawer` | false | Folds the navigation into a drawer on a narrow page. |
| `drawer-label` | `Menu` | The menu button's and drawer's name, a translation key. |

## A drawer on a narrow page

With `drawer`, the navigation folds away below 30 squares instead of standing above the work. A menu button stands in a one-square column before the header and opens the navigation in a drawer over the page, the same drawer the [Header](/4-page/header/#the-drawer) opens: focus stays inside it, Escape, its close button, a link or the page widening close it, and the page holds its scroll meanwhile. `ds-page-drawer` reports it opening and closing (`detail.open`); `openDrawer()` and `closeDrawer()` work it from code.

```html
<ds-page layout="sidebar" drawer>
  <ds-sidebar slot="nav" label="Projects"></ds-sidebar>
  <h1 slot="header">Inbox</h1>
  …
</ds-page>
```

## Setting the measure

A `column` or `centered` page is as wide as its measure: 32 squares and 16 by default. Set another in whole squares with `measure`:

```html
<ds-page layout="column" measure="28">…</ds-page>
```

`measure="28"` is exactly 28 squares at every scale. A fraction rounds to the nearest square, and zero, a negative number or text is ignored, so the layout keeps its own width. The attribute wins over `--ds-page-measure`, which is the same width as a custom property for styles that cannot reach the element's attributes; write it in squares too, never pixels: `--ds-page-measure: calc(28 * var(--ds-unit))`. `--ds-page-nav`, `--ds-page-aside` and `--ds-page-tile` set the other widths the same way.

### Standing on the grid

Centring a column in the width it has can leave it on a half square, off the grid lines the rest of the page is drawn on. `ds-page` shares the room beside the column out and rounds it down to whole squares, so the column always starts and ends on a grid line. When that room is an odd number of squares, the extra square falls on the trailing side. With less room than the measure needs, the column takes the width it has and stays one square in from the edge.

## In React

Import the typed adapter. It renders `<ds-page>` with `layout`, `divided`, `measure`, `fill` and `view` typed, so the product declares nothing of its own:

```tsx
import { Page } from "./design/react/page";

<Page layout="column" measure={28} divided>
  <h1 slot="header">Settings</h1>
  …
</Page>
```

The adapter does not register the element: import `4-page/ds-page` once in the browser entry, as for the other components. A product that writes `<ds-page>` directly instead needs a `JSX.IntrinsicElements` entry for it in its own declarations, because React does not know custom elements; the adapter replaces that entry. Sync 1 copies `react/page.ts` with the component when a product names `page` in its `components`.
