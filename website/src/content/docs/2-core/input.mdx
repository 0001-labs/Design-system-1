## When to use it

Give a field a visible label. A placeholder is a hint, not a label. Put the reason for an error in `error`, next to the field that needs attention.

## Attributes

| Attribute | Type | Default | What it does |
| --- | --- | --- | --- |
| `type` | string | `text` | Native input type, including email, password and number. |
| `name` | string | Empty | Key in form data. |
| `value` | string | Empty | Current value. |
| `label` | string | Empty | Visible field label. |
| `label-text` | string | Empty | Translation key for the label. |
| `placeholder` | string | Empty | Hint inside an empty field. |
| `placeholder-key` | string | Empty | Translation key for the hint. |
| `error` / `error-text` | string | Empty | Literal error or its translation key. |
| `disabled`, `readonly`, `required` | boolean | false | Native field states. |
| `variant` | string | `default` | `default`, `filled`, `outlined`, `row` (18px field in a 20px row), `field` (20px form control) or `plain` (transparent inline field). |
| `revealable` | boolean | false | Show a password visibility button; the public type stays `password`. |
| `quiet-focus` | boolean | false | Suppress the field focus box when its surrounding form supplies the focus treatment. |
| `inputmode` | string | Empty | Native mobile keyboard hint, such as `numeric`. |
| `aria-label` / `aria-labelledby` | string | Empty | Name the native field, including labels in the parent shadow root. |
| `aria-invalid` | string | Empty | Forward an application validation state to the native field. |
| `aria-describedby` | string | Empty | Copy the referenced description into the field's shadow root. |
| `spellcheck` | string | Empty | Native spelling hint, `true` or `false`. |

Native constraints include `min`, `max`, `step`, `pattern`, `minlength` and `maxlength`.

## Events and methods

```js
const field = document.querySelector('ds-input');
field.addEventListener('input-change', (event) => {
  console.log(event.detail.name, event.detail.value);
});
```

`input` and `change` bubble through shadow boundaries once, with the host’s current `value`. `input-change` also supplies `{ name, value }`.

The component participates in native forms through `ElementInternals`: a named field contributes to `FormData`, constraints and `error` affect form validity, reset restores its initial value and a disabled fieldset disables its control. `checkValidity()` and `reportValidity()` expose native validation.

Import `DS1/1-root/component-tokens.css` and set `--ds-sf` to the surface scale. The row treatment, password visibility, quiet focus and field colours are shared capabilities; configure them with attributes and `--ds-input-*` tokens rather than injecting styles or buttons into the shadow root.

### Surface scale

`--ds-sf` is an absolute scale: 1 gives a 20px row and 14px text; 1.5 gives 30px and 21px. Shared components resolve their measures at their own host, so a nested scale does not multiply its parent's scale. Add `data-ds-surface` to an ordinary layout container when its `--ds-unit`-based spacing should use that scale too.

```html
<section data-ds-surface style="--ds-sf: 1.5">
  <ds-input variant="field" label="Name"></ds-input>
  <ds-text literal>Scaled with the field</ds-text>
</section>
```

Colours and typefaces inherit as usual. Resolved dimensions such as `--ds-row-height` and `--ds-type-size-default` are local to each component; set a one-off override on that host. To carry a measure through a whole subtree, use an unscaled base token (`--ds-row-size`, `--ds-control-size`, `--ds-text-size`, `--ds-small-text-size`, `--ds-heading-text-size`, `--ds-text-leading`, `--ds-text-tracking`, `--ds-corner-size` or `--ds-card-corner-size`). Its component computes the scaled value. Keep DS1's default measures unless the existing product layout requires an explicit exception.

```html
<ds-input variant="row" type="password" name="password"
  aria-label="Password" autocomplete="current-password" revealable></ds-input>
```

`input-focus` and `input-blur` report focus changes. Call `focus()`, `blur()`, `select()` or `setSelectionRange()` on the component. `selectionStart`, `selectionEnd` and `valueAsNumber` expose the native field state. External HTML labels focus the field; Enter activates its form's enabled submit button unless an application keyboard handler cancels the event.

## React

Selecting `input` in a product's component copy also copies the shared `react/input.ts` adapter. Register the copied components through the product's browser entry, then import the adapter. It contains no visuals; `ds-input` owns the control. Registration must be browser-only in an application that renders on the server.

```tsx
import { Input, type InputElement } from './design/react/input';

<Input name="name" value={name} onChange={event => setName(event.target.value)}
  aria-label="Name" required />
```

The React adapter defaults to `variant="field"`. It supports controlled `value`, uncontrolled `defaultValue`, native hints such as `autoComplete`, keyboard and focus handlers, and refs typed as `InputElement`. Event `target` and `currentTarget` refer to the shared element. Controlled values are restored when an application rejects an edit or a form resets. React remains an optional peer dependency.

Use the input for text, email, password, number, date and time fields. File, colour, checkbox and radio inputs and composite comboboxes need their own shared controls. A combobox's listbox and active-option relationships cannot be passed through as plain text-field attributes.

### Shape preferences

Set `data-ds-shape="square"`, `"rounded"` or `"circular"` on the page, a
`data-ds-surface` container, or one shared control. DS1 supplies the corner
shape and the button inset; the product stores the preference. Rounded uses
4px arcs, or 8px squircles where supported. Circular keeps true round ends.
Every radius follows the component's own `--ds-sf`, including nested scales.
Without the attribute, controls use their normal DS1 defaults.

Buttons, fields, checkboxes, switches, selects and color fields share the
preference. Row and plain inputs and compact menu entries retain their square
edges. Multiline fields keep small 4px corners so a circular preference cannot
cut into writing; `--ds-textarea-radius` can configure those separately.
A surface can set the unscaled `--ds-corner-size`, `--ds-corner-shape`
and `--ds-button-inset` tokens; a specific field can set `--ds-input-radius`.
Do not inject product styles into a shared shadow root or restyle its native
light-DOM frame. Preference changes do not animate corners or padding.
