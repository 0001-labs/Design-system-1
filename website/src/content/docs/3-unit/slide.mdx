A slide shows several things side by side, each of its own width: tall cards and wide ones, a few in view and the next cut at the edge. A finger, a trackpad or the keyboard slides it sideways, and it stops with a card at its start. It can run on past its column to the window's edge while its first card keeps to the column, so it lines up with the writing above it.

A [carousel](/3-unit/carousel/) is the other way to show things side by side: one slide at a time, with page dots that say where you are. Use a slide for a strip of [cards](/2-core/card/) to browse, a carousel for a sequence to step through.

## Use it

```html
<ds-slide label="Work" bleed="end" buttons>
  <ds-card href="/lists" tone="sharp-blue" width="14" height="22" media="center">…</ds-card>
  <ds-card href="/portal" tone="ink" width="28" height="22" media="bleed">…</ds-card>
  <ds-card href="/money" tone="apple-green" width="14" height="22" media="center">…</ds-card>
</ds-slide>
```

Each element inside is an item, as wide as it is. Name the slide for what it shows with `label`, a translation key or, with `literal`, the words as written.

| Option | What it does |
| --- | --- |
| `bleed` | `none` (the default) keeps the strip in its box. `end` runs it on to the window's end edge, the first card still on the box's start, so nothing stands before the column. `both` runs it to both edges; cards slide out past the column's start. |
| `loop` | Holds the items three times over, so the strip has no end either way. The copies are hidden from assistive technology and never focused. |
| `autoplay` | Moves on a card at a time by itself: empty for every five seconds, or a number of milliseconds (at least 1000). Without `loop` it goes back to the first card after the last. |
| `buttons` | Previous and next buttons one square below, from the start. |
| `gap` | Squares between items, one by default and `0` for none. |
| `free` | Slides freely, without stopping at items. |

Options are read when the element connects; put a new element in its place to change them.

## Without Lit

```html
<section class="ds-slide" aria-label="Work" data-bleed="end" data-loop>
  <div class="ds-slide__track">
    <a class="ds-card" data-tone="sharp-blue" href="/lists">…</a>
    <a class="ds-card" data-tone="ink" href="/portal">…</a>
  </div>
</section>
<script type="module">
  import { startSlides } from "/ds1/0-face/slide.js";
  startSlides(document, { icons: "/ds1/x-icon/" });
</script>
```

`slide.css` comes with `controls.css`; Sync 1's `root` export copies the script with `"modules": ["slide"]`. The options are data attributes: `data-bleed`, `data-loop`, `data-autoplay` and `data-snap="none"`. Write `.ds-slide__previous` and `.ds-slide__next` buttons in a `.ds-slide__controls` row to have them wired; the script adds the row and the pause button for autoplay.

## Accessibility

- The element is a region named by `label`, and its items are a list.
- Every card stays an ordinary link or button in the tab order; a loop's copies are `inert` and hidden from assistive technology, so each card is reached once.
- The buttons are named "Previous slide" and "Next slide".
- The track is an ordinary scroller: swiping and trackpads move it, and so do the arrow keys where the browser lets a scroller take focus.

All the words are the shared words, in every language.

## Autoplay

A slide moves on by itself only when asked to, with `autoplay`. Then it always shows a pause button (named "Pause", then "Play"), holds while the pointer is over it, a finger is on it or the keyboard is in it, holds while it is out of view or the page is hidden, and never moves for a reader who asks for reduced motion. That meets WCAG 2.2.2 (Pause, Stop, Hide). Use it for a strip that shows off, never for one that holds something a person must read or act on. A [carousel](/3-unit/carousel/) never autoplays.
