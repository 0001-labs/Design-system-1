---

title: Menu
description: Shared action menus, suggestion lists and small choice grids.
---

`ds-menu` owns the face, keyboard navigation and placement of a list of choices.
Give each choice a native `option` or `menuitem` role. DS1 React `Button` keeps
the native button in light DOM, so its label, selected state and focus remain
available to the menu and to assistive technology.

An inline menu remains in document flow. Use `compact` inside an existing
shared dialog. Set `floating` and `open` for an anchored popup in the browser's
native popover layer, including inside a modal. Set `anchor` to its launcher
or writing field, or pass a viewport rectangle for a context menu. A rectangle
uses the focused control as its focus-return target. `placement="top"` prefers
the space above; the default is below. DS1 flips above the anchor when necessary and clamps the menu
to the visual viewport, including its keyboard and scale changes.

For suggestions, set `controller` to the native input or textarea and
`activeId` to the chosen option's ID. Arrow keys request the next enabled
option through the cancelable `ds-menu-active` event (`detail.id`); Enter
activates it. Focus stays in the field, including when pressing an option.
Home, End, modified keys and IME composition remain native editing commands.
The product owns the candidates, matching, insertion and field ARIA references.

For actions, focus starts on the selected or checked choice, falling back to
the first available choice, and returns to the launcher when the menu closes.
Set `trigger` to a native launcher to share click toggling and Arrow Up/Down
opening. Without a selection, Arrow Up starts at the last enabled choice.
The cancelable `ds-menu-toggle` event carries `detail.open`; a controlled owner
can decline it. Enter and Space still use the launcher's native click behavior.
Typing a label searches enabled choices; repeated letters cycle matching labels.
Products keep option data and callbacks, without their own navigation listeners.
`--ds-menu-width` sets a preferred width, still clamped to the viewport.
`columns` gives a small grid its horizontal and
vertical navigation. Hidden, disabled and nested choices are skipped.
Escape and outside presses request dismissal through `ds-menu-close`
(`detail.reason` is `escape` or `outside`). Cancel the event to decline the
request. Only the top menu handles Escape; it does not dismiss the surrounding
dialog. An outside press does not steal focus back from the chosen control.

In React, register `ds-menu` in the browser before hydration, then import
`Menu` from `DS1/react/menu`. Passing `open` creates a controlled floating menu;
`onOpenChange(open, reason)` requests a change (`trigger`, `escape` or `outside`).
Keep the menu mounted when it owns a `trigger`, including while closed.
`activeId` and `onActiveChange`
similarly keep selection controlled. Classes and styles place the host only.
Use shared buttons, text and icons inside it, with each entry one row high.

The menu stands on whole squares. Its line and the padding inside it make half
a square on each side, so n entries are n + 1 squares high, and a floating menu
half a square below its anchor puts its entries on the anchor's grid lines. It
has no shadow. A separator takes one square with its line. Every entry is one
square high whatever button styles surround it: shared buttons through their
entry role or `menu-item`, a library's own `<button>` or `<a>` held by the
menu. A floating menu rounds its anchor's width up, and the height it may take
down, to whole squares. `compact` entries are filled rows on a square's pitch,
19px with the 1px between them.
For a palette, set `columns` and place shared Button choices directly in the
menu. Each cell is one square. `data-ds-menu-start` on a Button starts a new
section after a short row. Separators span the grid; mark the first choice
after them as a section start. `data-ds-menu-row` on a Button makes a full-width
action such as Remove or Create. Shared arrow navigation follows those rows,
keeps the chosen column across full-width actions, and skips disabled choices.
Native `menuitemradio` buttons use `aria-checked` for the selected ring.
A supplied image can sit in a large `ds-icon`; `--ds-icon-ratio` describes its
width divided by height and `--ds-icon-radius` its corners. DS1 owns the
scaled image box. Product artwork and stored selection values stay in the app.
A `FilePicker` with `role="menuitem"` shares the row face and arrow navigation;
Enter and Space still open the native chooser. Keep the picker mounted until
its native change or cancel event, and copy its files before clearing its value.
Remove product popup positioning, keyboard listeners and appearance styles.


## Context and nested menus

Set `triggerMode="context"` with a native `trigger` to open at the pointer,
with Shift+F10 or the Context Menu key, or after a touch long press. Normal
left clicks still belong to the trigger. Touch movement cancels the gesture;
the click following a completed long press is consumed by the shared menu.
`openAt({x, y})` accepts a viewport point from an external control.

For a long or changing list, keep one menu mounted. Set `trigger` to the list
container and `contextSelector` to the marked row controls. DS1 delegates
right-click, keyboard and touch gestures to the matching descendant, including
rows inserted later. `ds-menu-toggle` includes `detail.trigger` (the actual row)
and `detail.point`; React receives the same detail as the third argument of
`onOpenChange`. Products read their row ID and choose actions. Native left clicks
remain unchanged; the click after a long press is consumed before React capture.
Give the marked row its own accessible name and `aria-haspopup="menu"`. DS1
returns focus to that row (or its native focusable descendant) and leaves container semantics unchanged.

`openAt(point, rowControl)` also opens the same menu from an external shortcut.
Keep confirmation and pending mutation state in the product, decline close and
new-row requests while pending, and restore enabled actions on rejection. Set
the menu's `disabled` property while pending to stop new trigger requests without
closing the current confirmation. When
confirmation replaces the focused action, DS1 focuses the first enabled choice.

Nested menus stay in their parent's DOM and use `triggerMode="submenu"`,
`trigger` and `anchor`. DS1 owns hover, forward/back arrow keys, viewport
flipping, Escape and focus return. `select()` dismisses the whole branch;
`requestClose()` is cancelable, and `ds-menu-close-focus` can decline focus
return when an action opens a field or dialog. A closed parent closes its
children too. Set `--ds-menu-width` for a preferred width within viewport bounds.

React products import `react/context-menu`: `ContextMenu`, `ContextMenuTrigger`,
`ContextMenuContent`, `ContextMenuItem`, `ContextMenuSub`, `ContextMenuSubTrigger`
and `ContextMenuSubContent`. Checkbox and radio entries compose native shared
Button menu rows; `onSelect` can prevent dismissal. Products supply actions,
checked values and labels. The adapter owns only React composition and state;
Lit owns the face, gestures, focus and placement. Register the selected shared
components in the browser before mounting the adapter.

`ContextMenuFilePicker` keeps the native chooser mounted through change and
cancel, copies the selected files and resets the input before `onFiles`.
Selection leaves the menu open so pending product state can disable the row.
Do not wrap it in an auto-closing action or add hidden click proxies.

For a title that opens an existing action surface, import `bindContextMenuTrigger`
from `DS1/3-unit/context-trigger`. It owns native right-click, ContextMenu / Shift+F10,
cancellable 600ms touch holds and suppression of only the matching next click.
The callback receives the viewport point, control and original event. Return
`false` to leave a declined gesture to the browser. `selection: true` suppresses
native title selection/callout while preserving vertical scrolling; `touch: false`
keeps an ordinary content surface's touch gestures. Call the returned `dispose()`
when removing the surface. Menu uses this same binding internally.

A menu with `triggerMode="manual"` opens only through `openAt(point, control)`.
This lets a title and a content surface invoke one shared menu without duplicate
popup or keyboard implementations. DS1 still owns placement, dismissal and focus
return to the native invoking control. Products retain permissions, action state
and pending-operation guards.
